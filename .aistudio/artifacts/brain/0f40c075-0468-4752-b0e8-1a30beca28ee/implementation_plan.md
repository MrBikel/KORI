# কড়ি (KORI) - পরবর্তী সুযোগের উন্নয়ন পরিকল্পনা: গুগল ড্রাইভ সিঙ্ক ও ক্লাউড অটো-ব্যাকআপ

এই পরিকল্পনায় 'কড়ি' প্রজেক্টের পরবর্তী ধাপে ব্যবহারকারীর সম্পূর্ণ ব্যক্তিগত তথ্য সুরক্ষাসহ গুগল ড্রাইভ সিঙ্ক, ব্যাকগ্রাউন্ড অটো-ব্যাকআপ এবং অ্যাপের শান্ত 'কালি-কাগজ' (Ink & Paper) নান্দনিকতার ধারাবাহিকতা বজায় রাখার বিশদ রোডম্যাপ তুলে ধরা হয়েছে।

## ইউজার রিভিউ ও গুরুত্বপূর্ণ সিদ্ধান্ত

> [!IMPORTANT]
> ব্যবহারকারী কর্তৃক নিশ্চিত করা প্রাথমিক সিদ্ধান্তসমূহ:
> - **প্রধান ফিচার**: ব্যবহারকারীর নিজস্ব গুগল ড্রাইভে এন্ড-টু-এন্ড এনক্রিপ্টেড স্বয়ংক্রিয় ব্যাকআপ ও সিঙ্ক ব্যবস্থা।
> - **ভিজ্যুয়াল অভিজ্ঞতা**: শান্ত, মার্জিত এবং বিভ্রান্তিমুক্ত 'কালি-কাগজ' (Ink & Paper) মিনিমালিস্ট থিম বজায় রাখা।

---

## ১. সার্বিক রূপরেখা ও মূল ধারণা (Overview & Core Concept)

- **উদ্দেশ্য ও সমাধান**: 
  বর্তমানে কড়িতে লোকাল ব্যাকআপ ফাইল (JSON) তৈরি ও রিস্টোর করা যায়। পরবর্তী সুযোগে এটিকে সরাসরি ব্যবহারকারীর গুগল ড্রাইভের লুক্কায়িত অ্যাপ ডাটা ফোল্ডারে (`drive.appdata`) যুক্ত করা হবে। এতে ফোন পরিবর্তন বা আনইনস্টল করলেও একটি ক্লিকেই সব হিসাব নিরাপদে উদ্ধার করা যাবে।
- **ব্যবহারকারী পর্যায়**: 
  যেসব ব্যবহারকারী নিজের আয়-ব্যয়ের হিসাব কোনো থার্ড-পার্টি বাণিজ্যিক সার্ভারে না রেখে সম্পূর্ণ ব্যক্তিগত মালিকানায় সুরক্ষিত রাখতে চান।
- **মূল সুবিধা**: 
  শূন্য বিজ্ঞাপন, জিরো-নলেজ ক্লাউড আর্কিটেকচার (ব্যবহারকারীর ডিভাইসেই ডাটা এনক্রিপ্ট হয়ে ড্রাইভে যাবে), এবং কোনো ইন্টারনেট না থাকলেও সম্পূর্ণ অফলাইন সক্ষমতা বজায় থাকবে।

## ২. ইউজার এক্সপেরিয়েন্স ও ভিজ্যুয়াল ডিজাইন (UX & Visual Design)

- **ক্লাউড সিঙ্ক ইন্টারঅ্যাকশন ফ্লো**:
  1. **প্রথম ড্রাইভ কানেক্ট**: 'আরও' (More) মেনুতে একটি শান্ত কার্ড থাকবে: *"গুগল ড্রাইভ ব্যাকআপ - বন্ধ রয়েছে"*; ট্যাপ করলে একটি মার্জিতBottomSheet খুলবে।
  2. **গুগল অ্যাকাউন্ট সংযোগ**: ওয়ান-ট্যাপ গুগল সাইন-ইন দিয়ে অ্যাকাউন্ট নির্বাচন; ব্যবহারকারীকে জানানো হবে ডাটা ড্রাইভে কীভাবে এনক্রিপ্ট থাকবে।
  3. **স্বয়ংক্রিয় সময়সূচি নির্বাচন**: ব্যবহারকারী বেছে নিতে পারবেন: *প্রতিদিন রাতে*, *সাপ্তাহিক*, অথবা *প্রতিটি হিসাব লেখার পর*।
  4. **সিঙ্ক স্ট্যাটাস ইন্ডিকেটর**: ডায়েরি স্ক্রিনের শীর্ষে একটি শান্ত সূক্ষ্ম চিহ্ন থাকবে (যেমন: *"শেষ ড্রাইভ ব্যাকআপ: আজ দুপুর ১২:৩০"*), কোনো বিরক্তিকর পপ-আপ থাকবে না।
  5. **ক্লাউড থেকে রিস্টোর প্রিভিউ**: নতুন ফোনে লগইন করলে ড্রাইভের ব্যাকআপ স্ক্যান করে এন্ট্রি সংখ্যা, তারিখ পরিসীমা এবং খাতের সারসংক্ষেপ দেখিয়ে নিশ্চিতকরণ চাওয়া হবে।

- **কালি-কাগজ (Ink & Paper) ভিজ্যুয়াল বজায় রাখা**:
  - **রং ও আবহ**: নরম পার্চমেন্ট ব্যাকগ্রাউন্ড (`#F8F6F0`), গভীর কালি-কালো টেক্সট (`#1C1B1A`), এবং ড্রাইভে সিঙ্ক অবস্থায় হালকা বনানী-সবুজ বা নীলচে মার্জিত অ্যাকসেন্ট (`#2D4A3E`)।
  - **টাইপোগ্রাফি**: বাংলা সংখ্যা এবং পরিষ্কার বাংলা লেটারিংয়ে রচিত তথ্য উপস্থাপন।
  - **অ্যানিমেশন**: শান্ত ফেড এবং জেন্টল স্প্রিং মোশন (৩০০ মিলিসেকেন্ডের নিচে), যা কোনো যান্ত্রিক বা ভারী ভাব তৈরি করবে না।

## ৩. গুরুত্বপূর্ণ প্রোডাক্ট ও প্রযুক্তিগত সিদ্ধান্ত (Trade-Offs)

- **সিদ্ধান্ত ১: নিজস্ব ক্লাউড ডাটাবেজ বনাম গুগল ড্রাইভ অ্যাপ-ডাটা**:
  - *গৃহীত পদক্ষেপ*: সরাসরি ব্যবহারকারীর পার্সোনাল Google Drive `appdata` ফোল্ডার ব্যবহার।
  - *কারণ*: এতে ব্যবহারকারীর গোপনীয়তা শতভাগ সুরক্ষিত থাকে, কোনো সার্ভার খরচ বা ডাটা ফাঁসের ঝুঁকি থাকে না।
  
- **সিদ্ধান্ত ২: ক্লাউড আপলোডের পূর্বে লোকাল এনক্রিপশন (Zero-Trust)**:
  - *গৃহীত পদক্ষেপ*: ব্যাকআপ এনভেলাপটি ড্রাইভে পাঠানোর আগে ব্যবহারকারীর ডিভাইসের অ্যান্ড্রোয়েড কি-স্টোর অথবা রিকভারি কি দিয়ে AES-GCM-256 এনক্রিপ্ট করা।
  - *কারণ*: গুগল ড্রাইভ অ্যাকাউন্ট কম্প্রোমাইজ হলেও কেউ ব্যক্তিগত আয়-ব্যয়ের খাতা পড়তে পারবে না।

- **সিদ্ধান্ত ৩: অ্যান্ড্রয়েড WorkManager ও ব্যাটারি অপ্টিমাইজেশন**:
  - *গৃহীত পদক্ষেপ*: ব্যাকগ্রাউন্ড সিঙ্কের জন্য `WorkManager` ব্যবহার করা, যার সাথে শর্ত থাকবে: ডিভাইস চার্জে থাকা এবং ওয়াই-ফাই বা আনমিটারড নেটওয়ার্ক সংযুক্ত থাকা।
  - *কারণ*: ব্যাকগ্রাউন্ডে ফোনের ব্যাটারি বা মোবাইল ডাটা খরচ হবে না।

## ৪. প্রযুক্তিগত আর্কিটেকচার ও ডাটা স্ট্র্যাটেজি (Technical Architecture)

```
┌─────────────────────────────────────────────────────────────────┐
│                    KORI Cloud Architecture                      │
├────────────────────────────────┬────────────────────────────────┤
│       Local Android Layer      │      Google Drive Cloud        │
│                                │                                │
│  ┌──────────────────────────┐  │   ┌────────────────────────┐   │
│  │ Room Database V3 (Paisa) │  │   │ Google Drive (appdata) │   │
│  │ - 20 Entities (Accounts, │  │   │ - KORI_BACKUP_V3.json  │   │
│  │   Transactions, Parties) │  │   │ - Snapshot History     │   │
│  └─────────────┬────────────┘  │   └───────────▲────────────┘   │
│                │               │               │                │
│  ┌─────────────▼────────────┐  │               │                │
│  │ LocalBackupRestoreService│  │               │                │
│  │ - Canonical JSON Export  │  │               │                │
│  │ - Checksum & AES-256     │  │               │                │
│  └─────────────┬────────────┘  │               │                │
│                │               │               │                │
│  ┌─────────────▼────────────┐  │               │                │
│  │ GoogleDriveSyncEngine    │──┼───────────────┘                │
│  │ - Google Identity Auth   │  │  (Encrypted Payload Transfer)  │
│  │ - WorkManager Scheduler  │  │                                │
│  │ - Conflict Merge Policy  │  │                                │
│  └──────────────────────────┘  │                                │
└────────────────────────────────┴────────────────────────────────┘
```

- **ডাটাবেজ ও এনভেলাপ ফরম্যাট**:
  - ক্লাউড এনভেলাপ হবে `KORI_CLOUD_V1`, যাতে ব্যাকআপ টাইমস্ট্যাম্প, রুম স্কিমা ভার্সন (V3), মোট এন্ট্রি সংখ্যা এবং SHA-256 চেকসাম থাকবে।
  - অফলাইন ও অনলাইন বিরোধ নিষ্পত্তিতে 'Last-Write-Wins' নীতি এবং পুরোনো ব্যাকআপের একটি অটোমেটিক হিস্ট্রি স্ন্যাপশট ড্রাইভে সংরক্ষিত থাকবে।

- **বাস্তবায়ন ধাপসমূহ**:
  1. `GoogleDriveSyncEngine` এবং `DriveAppDataRepository` তৈরি করা।
  2. `WorkManager` সিঙ্ক শিডিউলার ইন্টিগ্রেশন।
  3. 'আরও' (More) স্ক্রিনে মার্জিত ড্রাইভ সিঙ্ক সেটিংস ও অটো-ব্যাকআপ ডায়ালগ যোগ করা।
  4. ড্রাইভে ব্যাকআপ টেস্ট এবং নতুন ডিভাইসে রিস্টোর টেস্ট কেস প্রণয়ন করা।
